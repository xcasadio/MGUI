# ADR-0009: Animation V4: brushes as freezable, animatable data objects

- **Status**: Proposed (2026-09-14, waiting for the author's approval of `Docs/Tasks/animation-v4-tasks.md`)
- **Date**: 2026-09-14
- **Source**: this chantier: the author's question "how does Noesis handle animated brushes" after the V3 program, two read-only discoveries at HEAD `23cab97` and the author's answers to the four questions of `Docs/Tasks/animation-v4-tasks.md`

## Context

Facts verified at HEAD `23cab97` (V1 to V3 delivered by ADR-0006, ADR-0007 and ADR-0008):

- Ten value brushes are `readonly struct`s: `MGSolidFillBrush` (with a static palette `SolidFillBrushes` of 147 shared instances), `MGGradientFillBrush`, `MGDiagonalGradientFillBrush`, `MGTextureFillBrush`, `MGNineSliceFillBrush`, `MGProgressBarGradientBrush`, `MGUniformBorderBrush`, `MGDockedBorderBrush` (with a constructor-time `IsSolidColorsOnly` cache), `MGBandedBorderBrush`, `MGTexturedBorderBrush`. Six brushes are mutable classes without any freeze notion (four composites, `MGHighlightFillBrush`, `MGHighlightBorderBrush`). Every brush exposes `Copy()`; none overrides equality; no test asserts value equality of a whole brush; `MGSolidFillBrush` is constructed at 169 sites (95 in tests) and type-tested at 21 sites (`MGDockedBorderBrush`, `RequireSolid`, `MGUniformBorderBrush`).
- The engine never mutates a brush: every brush-valued target (`Background` and its state slots, `Background.Gradient`, `Background.DiagonalGradient`, `BorderBrush`) allocates a new brush per tick and writes it into the `Animation` (100) contribution of the store (`UIColorAnimationTargets.cs:101, 240`, `UIExtraAnimationTargets.cs:106-172`); a colour transition costs 104 bytes per tick, documented as an accepted cost.
- Equality guards: the eleven store write sites for brush pilots already use `ReferenceEqualityComparer.Instance`; `VisualStateSetting<T>` slot setters and `MGControlTemplate.ApplyTemplateValueCore` ("current value still equals the previous template default") use `EqualityComparer<T>.Default`, which is value equality for boxed structs today.
- Sharing: `MGTheme` holds 78 brush properties, `ThemeManagedGetter.GetValue(true)` clones on every read, `MGTheme.Copy()` recopies 49 brushes; `UIResourceReferenceApplicator` hands a `StaticResource` brush to every element by reference; XAML DTOs create one instance per `ToFillBrush` / `ToBorderBrush`; no element observes a brush (invalidation flows through element setters and the `VisualStateFillBrush` container).
- `MGHighlightBorderBrush` is the only brush with a clock: `Update` accumulates `(UA.AnimationDeltaTime ?? UA.FrameElapsed) / CycleDuration` into `AnimationProgress`, applies `StopOnMouseOver` / `StopOnClick` by setting `IsEnabled = false` on the brush itself when `Target` is hovered or pressed, so a shared instance stops for every element; `UpdateBaseArgs.AnimationDeltaTime` (added by V3) has no other consumer.
- NoesisGUI / WPF model (docs `Gui.Core._Brush`, `Gui.DependencySystem._Freezable`, forum threads 2598 and 442): `Brush : Animatable : Freezable : DependencyObject`; a brush is an animatable data object with no clock; a storyboard animates its properties through a property path resolved from an element; a frozen brush is immutable and shareable; animating an unfrozen shared brush animates every element referencing it; `Clone` copies values but not animations.

## Decision

1. Freezable contract: `IUIFreezable` (`IsFrozen`, `CanFreeze`, `Freeze()`) carried by `IFillBrush` and `IBorderBrush` through default interface members, implemented by an abstract `UIFreezableBrush` base (`ViewModelBase`, `ThrowIfFrozen` in every setter, recursive `Freeze`, `Copy()` = unfrozen deep copy; `Copy` keeps its name). A frozen brush never notifies; an unfrozen one raises `PropertyChanged` without allocation.
2. The ten value brushes become sealed mutable classes deriving from `UIFreezableBrush`, with settable notifying properties and unchanged constructors, `Copy()` and `Draw`; the six mutable classes adopt the contract and propagate `Freeze` / `Copy` to their children. Equality is reference equality (as in WPF); the guards that relied on struct value equality (`VisualStateSetting<T>` slot setters, `MGControlTemplate.ApplyTemplateValueCore`) use an explicit `UIBrushEquality.ValueEquals` helper (per-type, recursive for composites) instead; the store keeps reference equality.
3. Freezing policy: theme brushes (frozen at the end of `ThemeDefinitionBuilder.Build` and by every `MGTheme` setter), the static palette and static-resource brushes are frozen and shared without copy (`ThemeManagedGetter.GetValue` returns the frozen instance, `MGTheme.Copy()` shares, `VisualStateFillBrush` copies share their frozen slots); XAML inline brushes and code-created brushes stay unfrozen and element-owned; `Copy()` of a frozen brush is unfrozen.
4. Clone on animate, one rule for every base: the animated value of a brush pilot lives in the `Animation` (100) contribution of the store as today, but it is one object created when the run starts (`Copy()` of the effective brush below the animation, or a fresh brush of the expected type) and mutated per tick by the run, with no store write and no allocation per tick; restoring removes the contribution and the base reappears untouched. MGUI does not reproduce the Noesis behaviour "an unfrozen shared brush animates every element": the store's contribution layer plays the role of the dependency property animated value. The `VisualStateFillBrush` container and `MGBorder` subscribe to an unfrozen slot brush (so to an animated clone) to invalidate drawing, never to a frozen one.
5. Highlight on the engine: `MGHighlightBorderBrush` becomes a freezable configuration; `AnimationProgress` (name kept) is the current progress in [0, 1) written by an engine run through the new target `BorderBrush.Highlight.Progress` (double, simple, not observable); `Update` no longer accumulates time; `CycleDuration` becomes public; `AutoStart` (default true) lets the element host start a `RepeatForever` run of duration `CycleDuration` when the effective border brush is an enabled highlight brush (on attach, on border change, on enable), cancel it (`KeepCurrent`) on detach, border change or disable; `StopOnMouseOver` / `StopOnClick` act on the element's own animated clone, never on the base brush; `MGElement.ResumeBorderHighlight()` restarts; `Target` stays as an obsolete no-op. Two elements sharing a frozen highlight brush each have their own cycle.
6. `UpdateBaseArgs.AnimationDeltaTime` and its assignment in `MGDesktop.Update` are removed (a host reads `Desktop.Animations.Clock.DeltaTime`).
7. Closure: at the end of the program the four animation task files are deleted, the scenario index points at the architecture doc and the ADRs, and every code, test or sample comment citing a task file or a slice number is rewritten as a behaviour description; the history stays in ADR-0006 to ADR-0009.

Out of scope: generic property-path animation into a brush (`(Background).(SolidColorBrush.Color)`): the closed target registry stays, with existing paths and one new path; texture and nine-slice brushes stay non-interpolable; the highlight host does not look inside composite border brushes; the timers outside the engine (ADR-0006 decision 7) are untouched; the open points of ADR-0008 are not addressed here.

## Consequences

- No allocation per tick for any animation, colour and gradient targets included; a theme copy no longer deep-copies its brushes; a brush shared by a theme or a resource cannot be corrupted by application code (mutation throws).
- Behaviour changes to announce: a highlight brush shared by several elements gives each element its own cycle (aligned only when attached the same frame) and `StopOnMouseOver` / `StopOnClick` stop the hovered element only; assigning a brush to a theme freezes it; a struct-typed field or local that held a brush by value now holds a reference (null is possible); `AnimationDeltaTime` disappears from `UpdateBaseArgs`.
- Accepted costs: one `PropertyChanged` subscription per unfrozen brush held by a container or border, none for frozen brushes; one clone per animation run; a value-equality helper maintained per brush type.
- Risks tracked by the plan: the two value-equality guards (template default re-application, visual-state slot notification) must keep their current observable behaviour; `MGDockedBorderBrush` caches must follow property changes; the 169 construction sites compile unchanged but any code that assumed a non-null struct must guard against null.
- Deferred: generic brush property paths, interpolation of textures, a shared-cycle option for highlight brushes, freezing of `VisualStateFillBrush` containers themselves.
