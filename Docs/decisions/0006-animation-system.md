# ADR-0006: Animation system: render-only transform, desktop-owned engine and value model

- **Status**: Accepted (2026-09-12, author's answers to the fourteen questions of the readiness audit)
- **Date**: 2026-09-12
- **Source**: this chantier: audit of `mgui_animation_specifications.md` (author's specification, outside the repository) against HEAD `14e5f65`; program plan `Docs/Tasks/animation-tasks.md`

## Context

Facts verified at HEAD `14e5f65` (read-only audit):

- Time already flows as `TimeSpan` without any `GameTime` token in `MGUI.Core` or `MGUI.Shared`: `UpdateBaseArgs(TotalElapsed, FrameElapsed, ...)` (`MGUI.Shared/Rendering/RenderLoopArgs.cs:32`), built by the MonoGame backend from the host's `PreviewUpdate` (`MGUI.MonoGame.Integration/Rendering/MainRenderer.cs:168`). `MGDesktop.Update` (`MGUI.Core/UI/MGDesktop.cs:1355`) is the single per-frame entry point, exposes services as properties (`NavigationService`, `OverlayHost`) and raises `EndUpdate` last (`:1474`). The headless test runtimes feed frames explicitly (`ApplyFrame(new UpdateBaseArgs(...))`, `MGUI.Tests/Tooling/StableDiagnosticIdTests.cs:362-402`).
- `MGElement.Update` returns early for elements outside the viewport (`MGUI.Core/UI/MGElement.cs:3525` onwards) before `UpdateSelf` (`:3765`): a per-element tick would freeze hidden animations. Existing time-driven visuals read `UA.BA.FrameElapsed` in `UpdateSelf` or brush ticks (`MGHighlightBorderBrush`, `MGProgressButton.Duration`, `MGTextBlock.TextCharactersPerSecond`, `MGTimer` and `MGStopWatch` with their own `TimeScale`); the tooltip delay uses `DateTime.Now` (`MGElement.cs:3630`).
- `MGElement.Opacity` (`MGElement.cs:2990`) is multiplied down the tree at draw time (`:3865`). `RenderScale` (`ConditionalScaleTransform`, `:70` and `:3774`) is the only per-element render transform: a scale from the centre, chosen by the Pressed/Hovered visual state, applied through `IUIRenderContext.SetTransformTemporary` (`:3880-3890`); rotation and translation are supported by the matrix pipeline, and a transform change ends the current sprite or primitive batch (`MGUI.MonoGame.Integration/Rendering/DrawTransaction.cs:1036-1043`). Hit-testing ignores every element transform (`ContainsUnscaledInputPoint` tests `ActualLayoutBounds`, `MGElement.cs:2567`; documented limit `Docs/input-architecture.md:185`); only `MGWindow.Scale` inverts its matrix for input (`ConvertCoordinateSpace`, `GetTransform`).
- Drawing happens every frame (`MGDesktop.Draw`, `:1545`); a `Draw`-only invalidation is a no-op (`InvalidateTemplateValue`, `MGElement.cs:4102`), while a layout property write invalidates the window layout for the next frame.
- Every `MGElement` is an `INotifyPropertyChanged` through `ViewModelBase.NPC` (`MGUI.Shared/Helpers/ViewModelBase.cs:11-16`). The resolved value store (ADR-0005) defines the `Animation` precedence (100), its factory `UIValueResolutionSource.Animation(invalidation, name)` (`MGUI.Core/UI/Styling/UIValueResolutionSource.cs:47`), `Unset` as the fall-back to the next source, and tagged setters, for eight pilot keys only (`UIPilotProperty`); `Opacity` and `RenderScale` have no store and no base/animated distinction. The `Animation` level is not populated by the framework.
- `Background` is a `VisualStateFillBrush` container of one `IFillBrush` per primary state (`MGUI.Core/UI/VisualState.cs:331`); `MGSolidFillBrush` is a readonly struct carrying a `Color`; the text foreground is a `VisualStateSetting<Color?>`; a border brush is an `IBorderBrush` (`MGUniformBorderBrush(Color)` or `(IFillBrush)`). No API writes a `Color` to a background.
- The visual state is a pair of fixed enums (`PrimaryVisualState` Disabled/Selected/Focused/Normal, `SecondaryVisualState` Pressed/Hovered/None) recomputed each frame in `Update`, with a `VisualStateChanged` event (`MGElement.cs:2788`); there is no `Checked` state and no named visual state with setters.
- XAML: Portable.Xaml, DTO types in `MGUI.Core/UI/XAML/`, `[ContentProperty]` lists for property elements, `TypeConverter` for strings, `TimeSpan?` parsed natively (`Brushes.cs:541-553`); a `Setter` is applied by reflection on the DTO type (`Element.cs:924-943`), with no dotted path and no trigger model; no `Vector2` string converter exists.
- Lifecycle: no `Dispose` on `MGElement`; `SetParent` raises `OnParentChanged` (`MGElement.cs:915-929`); a closed window is removed from its lists but kept alive (`MGWindow.TryCloseWindow`, `:773-807`; `MGDesktop.NotifyWindowClosed`, `:1070`); ADR-0001 is the precedent for a lazily allocated per-element service tied to tree membership.
- No `TimelineControl` exists in the repository.

## Decision

Taken by the author on 2026-09-12 (the recommendation of each audit question, plus the answer on the editor):

1. A per-element render-only `RenderTransform` (translation, scale, rotation, origin) replaces `RenderScale` as the transform mechanism. `RenderScale` and its XAML attribute stay as sugar: the state-driven scale is composed into the same matrix at draw time.
2. Hit-testing follows the render transform from the first slice: the mouse position is mapped through the inverse of the element's transform and of its ancestors' transforms before the bounds test, in unscaled screen space, after the window scale conversion. Windows themselves keep `MGWindow.Scale`; a `RenderTransform` on an `MGWindow` is not honoured by occlusion and stays out of scope.
3. The base value of a non-pilot property (Opacity, RenderTransform components) is held by the animation engine; no new pilot is added to the resolved value store. Pilot properties are animated through the store with the `Animation` source and restored with `Unset`.
4. V1 triggers transitions from `VisualStateChanged` on the existing containers (the state-driven scale first); named visual states with setters, a `Checked` primary state and animated overlay cross-fades are deferred to V2.
5. Property targeting goes through a closed registry of typed accessors keyed by property path, extensible by the application; no reflection at runtime.
6. The code lives in `MGUI.Core/UI/Animation/`, namespace `MGUI.Core.UI.Animation`, with the framework's `UI*` naming.
7. One `UIAnimationClock` and one `UIAnimationManager` per `MGDesktop`, ticked at the head of `MGDesktop.Update`. The clock's `TimeScale` and pause do not drive the tooltip delay, `MGTimer` or `MGStopWatch`, which keep their own time.
8. Margin, Padding and MinHeight are animatable in V1 through their pilot setters and documented as layout-expensive; Width and Height are not animatable in V1.
9. Animations are cancelled when their owner leaves the tree (`OnParentChanged` to null) and when the window that displays them is closed; a re-shown window starts clean.
10. Defaults: cancellation restores the base value; completion holds the end value (`HoldEnd`).
11. Conflicts: one active animation per (target element, property path); an explicit animation replaces the transition running on the same path and starts from the current animated value; a property change during an explicit animation is ignored until the animation ends; a property change during a transition retargets it.
12. `MGHighlightBorderBrush`, `MGProgressButton.Duration`, `MGTextBlock.TextCharactersPerSecond`, `MGTimer` and `MGStopWatch` are untouched by this program and listed as later migration candidates.
13. The animation editor (timeline) belongs to the author's game engine, not to MGUI, for now. MGUI only keeps its keyframe model (V2) as plain data independent from the controls, so an external editor can produce it.
14. Delivery: one program file `Docs/Tasks/animation-tasks.md` (verified facts, decisions, V1 slices, V2 and V3 listed out of program) and this record.
15. (2026-09-12, after the first draft of the plan) NoesisGUI, which mirrors the WPF API, is the reference example for the transform semantics: the origin is a relative point in [0,1]² whose default is (0, 0), the top-left corner, as WPF's `RenderTransformOrigin`; the rotation angle is in degrees, as `RotateTransform.Angle`. The API shape stays the specification's (`Origin` carried by the transform object, not by the element).

Derived design (main session):

- Types: `UIRenderTransform` (mutable, `ViewModelBase`, `Translation` in unscaled layout pixels, `Scale` default `Vector2.One`, `Rotation` in degrees as in WPF's `RotateTransform.Angle` (author's decision of 2026-09-12; converted with `MathHelper.ToRadians` when the matrix is built), `Origin` relative in [0,1]² with default (0, 0) as in NoesisGUI and WPF (decision 15), `IsIdentity`); `UIAnimationClock`, `UIAnimationManager`, `UIAnimation`, `UIAnimation<T>`, `UIPropertyAnimation<T>`, `UIAnimationState`, `UIAnimationFillBehavior`, `UIAnimationCancelBehavior`, `IUIInterpolator<T>` and `UIInterpolators`, `IUIEasingFunction` and `UIEasing`, `IUIAnimationTarget<T>` and `UIAnimationTargets`, `UIAnimationCollection` (`element.Animations`), `UITransition<T>` and `UITransitionCollection` (`element.Transitions`).
- Draw composition: the local matrix is built in unscaled layout space from `LayoutBounds` translated by `DA.Offset` and composed before the current transform (`Local * CurrentSettings.Transform`), so the same matrix inverts for input; the state-driven scale of `RenderScale` keeps its own origin, the centre of the element, as a separate matrix composed before the transform's own matrix, so the default origin (0, 0) of decision 15 does not change today's hover and pressed behaviour; the clip target bounds are the axis-aligned bounds of the transformed rectangle, as `RenderScale` does today; the temporary transform is only pushed when the effective matrix is not the identity, so an element without transform costs no batch break.
- Zero cost when unused: `MGElement` gains two lazily allocated reference fields (`_RenderTransform`, and one animation slot holding the collections and the state-scale override), null after construction and untouched by update and draw; a desktop counter of active non-identity transforms gates the inverse hit-test walk so that no transform means no extra work per mouse event.
- Base value and `HoldEnd`: for a pilot, `HoldEnd` keeps the `Animation` contribution in the store until another animation on the same path starts or the owner's collection is cleared, so a later local write is shadowed and reported under the `Animation` source by the diagnostics; for a non-pilot the end value simply remains the CLR value and a later local write wins. This asymmetry is accepted and documented; transitions always end on the base value, so it does not affect them.
- `From` is optional on an animation: when absent, the animation starts from the value read at `Play`, which is what the conflict rule relies on.
- The clock does not clamp large frame deltas (a long pause completes the running animations on the next frame, deterministically).

## Consequences

- The `Animation` precedence level becomes populated by the framework for the pilot properties, and the diagnostics (`UIToolingService`) report it; the completeness sweep of pilot write sites must allow the engine's tagged writes.
- The input limit "RenderScale: la zone cliquable diverge des pixels dessines" disappears; the hit-test walk gains a gated inverse-transform step.
- Each animated non-identity transform ends and restarts the current batch: many simultaneously transformed elements cost draw calls, not layout; the documentation carries this cost instead of the layout cost the specification anticipates.
- Colour animations only interpolate solid brushes (`MGSolidFillBrush`, `MGUniformBorderBrush` over a solid fill); gradients, textures and nine-slices are not interpolated.
- `Thickness` is integer-based: an animated margin advances in whole pixels.
- With the top-left default origin, the specification's examples (hover 1.05, pressed 0.96, window opening 0.95 to 1) must set `Origin = (0.5, 0.5)` explicitly, in code or in XAML, exactly as `RenderTransformOrigin="0.5,0.5"` in NoesisGUI and WPF; the sample and the architecture document show it.
- Deferred to V2: storyboards and sequences, keyframes as a data model, named visual states with setters and `Checked`, overlay cross-fades, the fluent API, XAML visual states, style and theme integration of transitions, width and height. V3 (editor tooling) lives in the engine.
- Known limits accepted: a `RenderTransform` on a window is not honoured by window occlusion; a property change on a non-pilot during a held animation is not shadowed; the clock is per desktop, not per window.
